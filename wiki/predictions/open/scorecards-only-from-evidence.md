# Generating scorecards only from actual evidence keeps the governor honest

When migrating legacy predictions that lack scorecards, the engine should leave scorecard fields empty unless the page contains actual test results or observations. Hallucinating "draft" scorecards to unblock the governor is the exact failure mode conjecture was built to prevent — promoting plausible guesses into durable knowledge.

## Mechanism

The governor tracks learning rate via scorecard trends (prediction_accuracy, surprise, what_the_prediction_missed). If scorecards are generated from LLM inference rather than actual evidence, the governor's learning metric is contaminated. A governor that reports "learning is improving" based on hallucinated scorecards is worse than a governor that reports "insufficient data" — the first creates false confidence, the second correctly identifies a gap.

## Decisions

- If true: migrate flags missing scorecards but never fills them without evidence. Governor stays blind until real tests are run. This is correct.
- If false: draft scorecards with a "draft: true" flag would be accurate enough to provide useful governor signal without corrupting the metric.

## Test plan

1. Take vimx's 6 resolved predictions (h1, h2, h3, stateful-scan-dedup, page-state-diff, find-query-tool).
2. Have the LLM generate draft scorecards from page content alone.
3. Have the user independently write scorecards based on their memory of the actual outcomes.
4. Compare: accuracy of LLM-generated vs. user-written scorecards.

## Fail condition

Draft scorecards generated by the LLM match user-written scorecards >80% of the time (same prediction_accuracy grade, same surprise level). If the LLM can reliably infer outcomes from page content, the "never hallucinate" rule costs governor insight for no real integrity gain.
